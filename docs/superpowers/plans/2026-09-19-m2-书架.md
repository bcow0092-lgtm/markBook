# M2 书架 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 打通「导入一本书 → 书架显示 → 重启后仍在 → 能删掉」这条链路，EPUB 与 TXT 两种格式都支持。

**Architecture:** M1 已建好数据层（`repository` / `bookFiles` / `paths`）与 `app://` 协议，但它们还是三个孤立的工厂函数。M2 先加一个**组合根**把它们用 `app.getPath('userData')` 实例化并接上 IPC，然后按 §5.6 的 staging 流程实现导入，最后补渲染进程的书架页。TXT 的编码检测与章节切分放主进程（文本已在内存里，不必绕 IPC 传大字符串）；EPUB 的元数据与封面提取放渲染进程（复用 epub.js，不必在主进程引 zip/xml 解析库）。

**Tech Stack:** Electron 44 + React 19 + Zustand 5 + Tailwind CSS 4 + epub.js 0.3.93 + jschardet + iconv-lite。

**Spec:** [技术方案文档.md](../../../技术方案文档.md) —— 本计划实现 §5.6（导入流程）、§5.8（删除清理）、§3（目录结构）、§4.2（数据模型）、§11.1（书架页视觉）。前序里程碑见 [2026-09-19-m1-骨架与风险验证.md](./2026-09-19-m1-骨架与风险验证.md)。

## Global Constraints

- 平台：Windows 桌面应用。CI runner 必须 `windows-latest`。
- Node 24（技术方案 §6.5）。
- `epubjs` 锁定精确版本 `"0.3.93"`，不加 `^`。
- `vite` 锁 `^7`、`@vitejs/plugin-react` 锁 `^5`（技术方案 §9 的版本约束，动了两者会 ERESOLVE）。
- 窗口安全配置不可放宽：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
- CSP 的 `script-src` 保持 `'self'`；**不得设 `base-uri`**（§2.2）。
- 渲染进程不得直接接触 `fs` / `path`；一切文件操作走 IPC。
- **EPUB 解析必须自带超时**（§5.6 / §7.1）：损坏的 OPF 会让 epub.js 的 `display()` 既不 resolve 也不 reject。
- 交付前 `npm run verify` 必须全绿。每个任务结束前必须 commit。
- 注释与提交信息用中文，代码标识符用英文。

## 与设计文档的差异（§5.6 与 §4.2 已同步更新）

写计划时发现设计文档有几处不够严密，**已直接改进文档**，本计划按改进后的版本执行：

1. **`ImportResult` 补 `originalName`，staging 落一个 `{id}.staged.json`。** TXT 没有 epub.js 那样的元数据解析，书名只能从原始文件名推导，而文件名只有主进程知道；`commit` 阶段还要用它做书名兜底，但那时手上的文件名已经是 `{id}.epub` 这种、读不出原名了。因此 `importStaged` 把 `{ originalName, format, sourceEncoding }` 写进 staging，`commitImport` 从那里读。

2. **章节索引留在主进程。** 这一条原本是设计文档里的**自相矛盾**：§5.6 的流程图一边画着主进程「章节切分，结果暂存内存」，一边又让渲染进程在 `commitImport` 的载荷里回传 `chapters?` —— 两件事不可能同时成立，那是更早版本（渲染进程切分）留下的残留。现已删除 `chapters?`，章节索引全程留在主进程：import 时写 `.staging/{id}.chapters.json`，commit 时搬到 `chapters/{id}.json`。

   之所以经 staging 文件而不是主进程内存（流程图原写「暂存内存」）：内存方案会让 `abort` 需要同时维护「文件」和「内存表」两份状态，加一种 staging 产物时容易只改一边。统一落到文件后，`abort` 与启动清理共用同一个「扫目录」机制。

   配套：`bookFiles.abort` 改为**按前缀清扫** staging，不再写死文件名。

3. **色值分两处定义。** §11.4 说集中到 `theme.ts`，但 Tailwind 4 的主题定义在 CSS 里。最终是：Tailwind 的 `@theme` 块管 CSS 类，`theme.ts` 管需要传给 epub.js 主题系统的 JS 值（§5.3）。两处各有一份、注释互相指认。

```ts
import { createPaths, ensureDirs, clearStaging, type AppPaths } from './paths'
import { createRepository, type Repository } from './repository'
import { createBookFiles, type BookFiles } from './bookFiles'

export interface AppContext {
  paths: AppPaths
  repo: Repository
  files: BookFiles
}

/**
 * 组合根。把三个服务用同一个 root 实例化并接起来 —— 服务本身都不 import
 * electron，root 由调用方（main/index.ts 用 app.getPath('userData')）传入，
 * 因此这里可以在 vitest 的 Node 环境下直接跑。
 */
export async function createContext(root: string): Promise<AppContext> {
  const paths = createPaths(root)
  await ensureDirs(paths)
  // 清掉上次运行中途崩溃留下的半成品（技术方案 §5.6）
  await clearStaging(paths)

  const repo = createRepository(paths.libraryFile)
  await repo.load()

  return { paths, repo, files: createBookFiles(paths) }
}
```

`src/main/services/txt/encoding.ts`：

```ts
import jschardet from 'jschardet'
import iconv from 'iconv-lite'

export interface DecodeResult {
  text: string
  encoding: string
}

/** 只探测开头这么多个字节。jschardet 对全书做统计没有额外收益，几十 MB 反而慢。 */
const DETECT_WINDOW = 64 * 1024

/**
 * jschardet 报出来的名字与 iconv-lite 接受的名字不完全一致。
 * GB2312 的字符集是 GBK 的子集、GBK 又是 GB18030 的子集，一律上提到
 * GB18030 —— 用超集解子集的字节永远安全，反之会丢字符。
 */
function normalizeEncoding(name: string | undefined | null): string {
  if (!name) return 'UTF-8'
  const n = name.toUpperCase()
  if (n === 'GB2312' || n === 'GBK' || n === 'GB18030' || n === 'X-GBK') return 'GB18030'
  if (n === 'ASCII') return 'UTF-8'
  return name
}

export function detectEncoding(buf: Buffer): string {
  if (buf.length === 0) return 'UTF-8'
  // BOM 优先于统计检测
  if (buf.length >= 3 && buf[0] === 0xef && buf[1] === 0xbb && buf[2] === 0xbf) return 'UTF-8'
  if (buf.length >= 2 && buf[0] === 0xff && buf[1] === 0xfe) return 'UTF-16LE'
  if (buf.length >= 2 && buf[0] === 0xfe && buf[1] === 0xff) return 'UTF-16BE'

  const result = jschardet.detect(buf.subarray(0, DETECT_WINDOW))
  return normalizeEncoding(result?.encoding)
}

export function decodeText(buf: Buffer, forcedEncoding?: string): DecodeResult {
  const encoding = forcedEncoding ?? detectEncoding(buf)
  const text = iconv.decode(buf, encoding)
  // iconv-lite 会把 BOM 解成 U+FEFF 留在正文开头，章节正则的 ^ 锚点会被它顶掉
  return { text: text.charCodeAt(0) === 0xfeff ? text.slice(1) : text, encoding }
}
```

```ts
import type { ChapterIndex } from '@shared/types'

export interface ChapterSplitResult {
  chapters: ChapterIndex[]
  totalCharacters: number
  degraded: boolean
}

/** 降级时按固定字数等分 */
export const FALLBACK_CHARS = 5000

/** 标题行最多这么长。超过就认为是一句话而不是标题。 */
const MAX_TITLE_LINE = 40

/**
 * 三条正则都要求**独占一行**。缺了行首行尾锚点的话，「他第三章还没读完」
 * 这种正文会被当成标题（技术方案 §5.4）。
 */
const PATTERNS: RegExp[] = [
  /^[ \t]*([^\n]{1,32}第[一二三四五六七八九十百千零〇0-9]{1,8}[章节回卷篇][^\n]{0,20})[ \t]*$/gm,
  /^[ \t]*(Chapter\s+[0-9IVXLC]{1,6}[^\n]{0,30})[ \t]*$/gim,
  /^[ \t]*([0-9]{1,4}[.、][^\n]{0,30})[ \t]*$/gm,
]

// 降级阈值（技术方案 §5.4 的判定表）
const MIN_CHAPTERS = 3
const MAX_CHAPTERS = 1000
const MIN_AVG_LENGTH = 500

interface TitleHit {
  index: number
  title: string
}

function findTitles(text: string): TitleHit[] {
  const hits: TitleHit[] = []
  const seen = new Set<number>()
  for (const re of PATTERNS) {
    for (const m of text.matchAll(re)) {
      const title = m[1].trim()
      if (title.length > MAX_TITLE_LINE) continue
      const index = m.index ?? 0
      if (seen.has(index)) continue
      seen.add(index)
      hits.push({ index, title })
    }
  }
  return hits.sort((a, b) => a.index - b.index)
}

function splitByTitles(text: string, hits: TitleHit[]): ChapterIndex[] {
  return hits.map((hit, i) => ({
    title: hit.title,
    start: hit.index,
    end: i + 1 < hits.length ? hits[i + 1].index : text.length,
  }))
}

function splitBySize(text: string, size = FALLBACK_CHARS): ChapterIndex[] {
  if (text.length === 0) return []
  const out: ChapterIndex[] = []
  for (let start = 0; start < text.length; start += size) {
    const end = Math.min(start + size, text.length)
    out.push({ title: `第 ${out.length + 1} 部分`, start, end })
  }
  return out
}

/**
 * 切分章节。命中标题但结果不可信时降级为按固定字数等分 —— 降级判定的
 * 三条规则见技术方案 §5.4，任一不满足即降级。
 */
export function splitChapters(text: string): ChapterSplitResult {
  const totalCharacters = text.length
  if (totalCharacters === 0) {
    return { chapters: [], totalCharacters: 0, degraded: false }
  }

  const hits = findTitles(text)
  const plausible =
    hits.length >= MIN_CHAPTERS &&
    hits.length <= MAX_CHAPTERS &&
    (totalCharacters - hits[0].index) / hits.length >= MIN_AVG_LENGTH

  if (plausible) {
    return { chapters: splitByTitles(text, hits), totalCharacters, degraded: false }
  }
  return { chapters: splitBySize(text), totalCharacters, degraded: true }
}
```

```ts
const SUPPORTED: BookFormat[] = ['epub', 'txt']

function parseFormat(srcPath: string): BookFormat {
  const ext = extname(srcPath).slice(1).toLowerCase()
  if (!SUPPORTED.includes(ext as BookFormat)) {
    throw new Error(`不支持的格式：${ext || '(无扩展名)'}，只支持 .epub 与 .txt`)
  }
  return ext as BookFormat
}

/** 去掉扩展名作为书名兜底。渲染进程侧有一份同样规则的实现，两处要一起改。 */
export function titleFromFileName(name: string): string {
  const base = basename(name)
  const ext = extname(base)
  return (ext ? base.slice(0, -ext.length) : base).trim() || '未命名'
}

/**
 * staging 期的元信息。commit 需要知道原始文件名（书名兜底）与原始编码，
 * 这两样在 `{id}.epub` 这样的文件名里都读不出来。
 *
 * 写在 staging 而不是内存里：渲染进程崩溃时内存就没了，而 staging 里的
 * 东西由 abort 或下次启动统一清掉，生命周期天然自洽。
 */
interface StagedMeta {
  originalName: string
  format: BookFormat
  sourceEncoding: string | null
}

/**
 * 第一步：把源文件复制进 staging，TXT 顺带转码并切分章节。
 *
 * 刻意不依赖 dialog / ipcMain —— handler 只负责弹对话框，业务在这里，
 * 于是这段逻辑能在 vitest 的 Node 环境下直接测。
 */
export async function importStaged(ctx: AppContext, srcPath: string): Promise<ImportResult> {
  const format = parseFormat(srcPath)
  const id = randomUUID()

  await ctx.files.stageFile(srcPath, id, format)

  let sourceEncoding: string | null = null
  if (format === 'txt') {
    const raw = await readFile(srcPath)
    const decoded = decodeText(raw)
    sourceEncoding = decoded.encoding
    await writeFile(join(ctx.paths.staging, `${id}.utf8.txt`), decoded.text, 'utf8')

    const split = splitChapters(decoded.text)
    const chapterFile: ChapterFile = {
      totalCharacters: split.totalCharacters,
      chapters: split.chapters,
    }
    await writeFile(
      join(ctx.paths.staging, `${id}.chapters.json`),
      JSON.stringify(chapterFile),
      'utf8',
    )
  }

  const meta: StagedMeta = { originalName: basename(srcPath), format, sourceEncoding }
  await writeFile(join(ctx.paths.staging, `${id}.staged.json`), JSON.stringify(meta), 'utf8')

  return { id, format, originalName: meta.originalName, sourceEncoding }
}

/** 第二步：渲染进程解析出元数据后提交 */
export async function commitImport(
  ctx: AppContext,
  id: string,
  payload: CommitPayload,
): Promise<Book> {
  const meta = JSON.parse(
    await readFile(join(ctx.paths.staging, `${id}.staged.json`), 'utf8'),
  ) as StagedMeta

  const chapters =
    meta.format === 'txt'
      ? (JSON.parse(
          await readFile(join(ctx.paths.staging, `${id}.chapters.json`), 'utf8'),
        ) as ChapterFile)
      : undefined

  const result = await ctx.files.commit(id, meta.format, {
    sourceEncoding: meta.sourceEncoding,
    chapters,
    cover: payload.coverBase64
      ? { base64: payload.coverBase64, ext: payload.coverExt ?? 'png' }
      : null,
  })

  const book: Book = {
    id,
    // 主进程侧兜底：渲染进程传来的书名可能是空的（§11.1 的降级规则）
    title: payload.title.trim() || titleFromFileName(meta.originalName),
    author: payload.author.trim(),
    format: meta.format,
    fileName: result.fileName,
    coverFileName: result.coverFileName,
    size: (await stat(join(ctx.paths.books, result.fileName))).size,
    addedAt: Date.now(),
    lastReadAt: null,
    progress: null,
    sourceEncoding: result.sourceEncoding,
    locationsReady: meta.format === 'txt',
  }

  await ctx.repo.upsertBook(book)
  await ctx.repo.flush()
  return book
}

export async function abortImport(ctx: AppContext, id: string): Promise<void> {
  await ctx.files.abort(id)
}

/** 删除：先从 library.json 移除并落盘，再删文件（技术方案 §5.8） */

  if (!book) return
  await ctx.repo.removeBook(id)
  await ctx.repo.flush()
  await ctx.files.remove(id, book.format, book.coverFileName)
```

`src/renderer/src/lib/epubMeta.ts`：

```ts
import ePub from 'epubjs'

export interface BookMeta {
  title: string
  author: string
  coverBase64?: string
  coverExt?: string
}

/** 解析超时。损坏的 OPF 会让 epub.js 永不 settle（技术方案 §7.1）。 */
export const DEFAULT_META_TIMEOUT_MS = 15_000

function withTimeout<T>(p: Promise<T>, ms: number, label: string): Promise<T> {
  return Promise.race([
    p,
    new Promise<T>((_, reject) =>
      setTimeout(() => reject(new Error(`${label} 超时（${ms}ms）`)), ms),
    ),
  ])
}

const EXT_BY_MIME: Record<string, string> = {
  'image/png': 'png',
  'image/jpeg': 'jpg',
  'image/gif': 'gif',
  'image/webp': 'webp',
  'image/svg+xml': 'svg',
}

function blobToBase64(blob: Blob): Promise<string> {
  return new Promise((resolve, reject) => {
    const reader = new FileReader()
    reader.onload = () => {
      const url = String(reader.result)
      resolve(url.slice(url.indexOf(',') + 1))
    }
    reader.onerror = () => reject(reader.error ?? new Error('读取封面失败'))
    reader.readAsDataURL(blob)
  })
}

/**
 * 用 epub.js 打开 staging 里的书，取出书名、作者与封面。
 *
 * 只做元数据提取，不渲染 —— 因此不需要 rendition，也就绕开了「损坏的 OPF
 * 会让 display() 挂起」那个坑；但仍要加超时，因为 book.ready 在解析畸形
 * 文件时同样可能不 settle。
 */
export async function extractEpubMeta(
  bookUrl: string,
  timeoutMs = DEFAULT_META_TIMEOUT_MS,
): Promise<BookMeta> {
  const book = ePub(bookUrl)
  try {
    const failure = new Promise<never>((_, reject) => {
      book.on('openFailed', (e: unknown) => reject(new Error(`打开失败：${String(e)}`)))
    })

    const meta = await withTimeout(
      Promise.race([book.loaded.metadata, failure]),
      timeoutMs,
      '解析元数据',
    )

    let coverBase64: string | undefined
    let coverExt: string | undefined
    try {
      const coverUrl = await withTimeout(
        Promise.race([book.coverUrl(), failure]),
        timeoutMs,
        '提取封面',
      )
      if (coverUrl) {
        const blob = await fetch(coverUrl).then((r) => r.blob())
        coverBase64 = await blobToBase64(blob)
        coverExt = EXT_BY_MIME[blob.type] ?? 'png'
      }
    } catch {
      // 没有封面、或封面提取失败都不该让整次导入失败
    }

    return {
      title: (meta.title ?? '').trim(),
      author: (meta.creator ?? '').trim(),
      coverBase64,
      coverExt,
    }
  } finally {
    try {
      book.destroy()
    } catch {
      /* 忽略 */
    }
  }
}
```

- [ ] **Step 4: 写导入编排**

`src/renderer/src/lib/import.ts`：

```ts
import type { Book, MarkReaderApi } from '@shared/types'
import { extractEpubMeta } from './epubMeta'

/** 去掉扩展名作为书名兜底 —— 与主进程的 titleFromFileName 保持同一规则 */
export function titleFromFileName(name: string): string {
  const base = name.replace(/^.*[\\/]/, '')
  const dot = base.lastIndexOf('.')
  return (dot > 0 ? base.slice(0, dot) : base).trim() || '未命名'
}

/**
 * 一次完整的导入：调主进程 staging → 解析元数据 → 提交；任一步失败都回滚。
 *
 * api 作为参数传入而不是直接用 window.api，这样这条流程能在单测里注入假实现。
 */
export async function importBookFlow(
  api: MarkReaderApi,
  timeoutMs?: number,
): Promise<Book | null> {
  const staged = await api.importBook()
  if (!staged) return null // 用户取消

  try {
    const meta =
      staged.format === 'epub'
        ? await extractEpubMeta(`app://local/books/.staging/${staged.id}.epub`, timeoutMs)
        : { title: titleFromFileName(staged.originalName), author: '' }

    return await api.commitImport(staged.id, {
      title: meta.title,
      author: meta.author,
      coverBase64: meta.coverBase64,
      coverExt: meta.coverExt,
    })
  } catch (err) {
    // 回滚。即便这一步也失败，books/.staging/ 会在下次启动时被清空（§5.6）
    await api.abortImport(staged.id).catch(() => {})
    throw err
  }
}
```
