# M4 TXT 阅读 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 书架上的 TXT 也能点开分页阅读，翻页、跳目录、拖进度条、位置恢复全部可用。

**Architecture:** `TxtEngine` 实现 M3 定稿的 `ReaderEngine` 接口，上层阅读页不感知格式差异。分页用 **CSS 多列布局**（§5.4，M1 已实测确认成立），翻页靠 `translateX`；文本按章节挂载，只渲染当前章 ±1。散文与偏移的换算全部抽成纯函数放在 `lib/txtPaging.ts` —— 与 M3 同样的理由：DOM 相关的东西难测，把判断逻辑剥出来是让它有覆盖的唯一现实办法。

**Tech Stack:** Electron 44 + React 19 + Zustand 5 + Tailwind CSS 4。TXT 侧**不引入任何新依赖**。

**Spec:** [技术方案文档.md](../../../技术方案文档.md) —— 本计划实现 §5.4 第（3）节（分页渲染与大文件策略）、§5.5（TXT 的进度定义）、§5.7（`ReaderEngine`）。前序里程碑见 [M1](./2026-09-19-m1-骨架与风险验证.md)、[M2](./2026-09-19-m2-书架.md)、[M3](./2026-09-25-m3-epub阅读.md)。

## 与设计文档的差异

1. **`EngineOptions` 的 `loadLocations` / `saveLocations` 改成可选。** 它们是 EPUB 专用的（位置索引只 epub.js 需要），TxtEngine 实现时会变成空壳。改可选之后 EPUB 侧照旧传，TXT 侧不传。
2. **`IndexedTocEntry.spineIndex` 改名为 `index`。** 这个共享接口现在有第二个实现了，而 TXT 没有 spine 概念，用章节序号。名字继续叫 spineIndex 会误导后来的读者。
3. **TXT 正文的段落规则**：每个非空行算一段，段首缩进两字、段间留白。§5.4 只定义了分页方式，没定义文本怎么变段落。
4. **章节内的页码 → 字符偏移是近似值**：`chapter.start + round(chapterLength * page / pageCount)`。精确到页，不是精确到字符。对进度显示足够（一个 5000 字的章分成 20 页，误差上限约 0.05% 全书），但 §5.5 把 TXT 标成 `percentageExact: true` 需要改措辞为「页粒度精确」。

```ts
/**
 * 目录项 + 它在正文里的位置。
 *
 * `index` 的含义随格式而变：EPUB 是 spine 序号，TXT 是章节序号。两者都是
 * 「越大越靠后」，所以 findCurrentChapter 的判据对两种格式都成立。
 * 取不到时记 -1。
 */
export interface IndexedTocEntry {
  title: string
  index: number
}

export function findCurrentChapter(toc: IndexedTocEntry[], currentIndex: number): ChapterRef {
  let found: ChapterRef = { index: -1, title: '' }
  for (let i = 0; i < toc.length; i++) {
    const entry = toc[i]
    if (entry.index < 0) continue
    if (entry.index > currentIndex) break
    found = { index: i, title: entry.title }
  }
  return found
}
```

`src/renderer/src/lib/txtPaging.ts`：

```ts
import type { ChapterIndex } from '@shared/types'

/**
 * TXT 的页码 / 章节 / 字符偏移换算。
 *
 * 全是纯函数、不碰 DOM —— 分页本身依赖 Chromium 的多列布局，测起来必须
 * 起真实渲染环境；把这些换算剥出来，至少让「读到哪了」这件事有覆盖。
 */

function clamp01(n: number): number {
  if (!Number.isFinite(n)) return 0
  return Math.min(1, Math.max(0, n))
}

/** 全文字符偏移落在第几章。越界时夹到首尾，空表返回 -1 */
export function chapterIndexOf(chapters: ChapterIndex[], offset: number): number {
  if (chapters.length === 0) return -1
  if (offset <= chapters[0].start) return 0

  for (let i = 0; i < chapters.length; i++) {
    if (offset < chapters[i].end) return i
  }
  return chapters.length - 1
}

/**
 * 章节内的第几页对应哪个字符偏移。
 *
 * **这是近似值** —— 精确到页而不是精确到字符。要知道某一页第一个字到底是
 * 哪个字符，得用 Range 去量列边界，对每次翻页都做一遍不值得。对进度显示
 * 足够：一个 5000 字的章分成 20 页，误差上限约 0.05% 全书。
 */
export function offsetFromPage(
  chapter: ChapterIndex,
  pageIndex: number,
  pageCount: number,
): number {
  const length = chapter.end - chapter.start
  if (pageCount <= 0 || length <= 0) return chapter.start
  const page = Math.min(pageCount - 1, Math.max(0, Math.floor(pageIndex)))
  // 用 pageCount 而不是 pageCount - 1 当分母：最后一页的起点不该是章节末尾
  return chapter.start + Math.round((length * page) / pageCount)
}

export function percentageFromOffset(offset: number, totalCharacters: number): number {
  if (totalCharacters <= 0) return 0
  return clamp01(offset / totalCharacters)
}

export function offsetFromPercentage(percentage: number, totalCharacters: number): number {
  if (totalCharacters <= 0) return 0
  return Math.round(clamp01(percentage) * totalCharacters)
}
```

- [ ] **Step 2: 写引擎**

`src/renderer/src/components/reader/TxtEngine.ts`：

```ts
import type { ChapterFile, ReadingProgress } from '@shared/types'
import {
  findCurrentChapter,
  seekTarget,
  type IndexedTocEntry,
} from '../../lib/readerProgress'
import {
  chapterIndexOf,
  offsetFromPage,
  offsetFromPercentage,
  percentageFromOffset,
} from '../../lib/txtPaging'
import type { EngineOptions, ReaderEngine } from './engine'

/** 列间距。与 §5.4 的实测数据一致 */
const GAP = 40

/**
 * TXT 阅读引擎。分页用 CSS 多列布局，翻页靠 translateX（§5.4）。
 *
 * 文本按章挂载：一次性 fetch 全文（内存里留个几十 MB 的字符串不是瓶颈），
 * 但 DOM 里只放当前章 ±1 —— 真正的瓶颈是几十万个节点。
 */
export function createTxtEngine(opts: EngineOptions): ReaderEngine {
  const viewport = document.createElement('div')
  viewport.className = 'txt-viewport'
  const columns = document.createElement('div')
  columns.className = 'txt-columns'
  viewport.appendChild(columns)
  opts.container.appendChild(viewport)

  let chapters: ChapterFile = { totalCharacters: 0, chapters: [] }
  let text = ''
  let toc: IndexedTocEntry[] = []
  let currentChapter = 0
  let pageIndex = 0
  let pageCount = 1
  let destroyed = false

  /** 每页宽 = 视口宽。必须与 column-width 相等，否则浏览器会拉伸列宽填满 */
  const pageWidth = (): number => Math.max(1, viewport.clientWidth)
  const pageHeight = (): number => Math.max(1, viewport.clientHeight)

  function applyGeometry(): void {
    columns.style.width = `${pageWidth()}px`
    columns.style.height = `${pageHeight()}px`
    columns.style.columnWidth = `${pageWidth()}px`
    columns.style.columnGap = `${GAP}px`
  }

  /** 列数 = (scrollWidth + gap) / (pageWidth + gap)，与 M1 实测的算法一致 */
  function measurePages(): void {
    const w = pageWidth()
    pageCount = Math.max(1, Math.round((columns.scrollWidth + GAP) / (w + GAP)))
    if (pageIndex > pageCount - 1) pageIndex = pageCount - 1
  }

  function paint(): void {
    columns.style.transform = `translateX(-${(pageWidth() + GAP) * pageIndex}px)`
  }

  function renderChapter(): void {
    const ch = chapters.chapters[currentChapter]
    if (!ch) {
      columns.textContent = '（空文件）'
      return
    }
    const slice = text.slice(ch.start, ch.end)
    // 每个非空行算一段：中文小说是「一段一行」，段首缩进两字、段间留白
    const fragment = document.createDocumentFragment()
    for (const line of slice.split('\n')) {
      const trimmed = line.trim()
      if (trimmed === '') continue
      const p = document.createElement('p')
      p.textContent = trimmed
      fragment.appendChild(p)
    }
    columns.replaceChildren(fragment)
    applyGeometry()
    measurePages()
    paint()
  }

  function currentOffset(): number {
    const ch = chapters.chapters[currentChapter]
    if (!ch) return 0
    return offsetFromPage(ch, pageIndex, pageCount)
  }

  function emitProgress(): void {
    if (destroyed) return
    const offset = currentOffset()
    const chapter = findCurrentChapter(toc, currentChapter)
    opts.callbacks.onRelocated({
      location: offset,
      percentage: percentageFromOffset(offset, chapters.totalCharacters),
      // TXT 的进度由字符偏移直接算出，不依赖任何后台索引
      percentageExact: true,
      chapterIndex: chapter.index,
      chapterTitle: chapter.title,
    })
  }

  /** 切到某一章并渲染。与接口方法 goToChapter 分开命名，免得里外混在一起看不出来 */
  function switchChapter(index: number, page = 0): void {
    if (index < 0 || index >= chapters.chapters.length) return
    currentChapter = index
    pageIndex = page
    renderChapter()
    emitProgress()
  }

  return {
    async load(book, location) {
      const [rawText, rawChapters] = await Promise.all([
        fetch(`app://local/txt-cache/${book.id}.txt`).then((r) => r.text()),
        fetch(`app://local/chapters/${book.id}.json`).then(
          (r) => r.json() as Promise<ChapterFile>,
        ),
      ])
      if (destroyed) return

      text = rawText
      chapters = rawChapters
      toc = chapters.chapters.map((c, i) => ({ title: c.title, index: i }))
      opts.callbacks.onToc(toc)

      // 用调用方传来的 location 而不是 book.progress —— 接口就是这么约定的，
      // 调用方（阅读页）负责决定恢复到哪里
      const offset = typeof location === 'number' ? location : 0
      switchChapter(Math.max(0, chapterIndexOf(chapters.chapters, offset)))
    },

    prev() {
      if (pageIndex > 0) {
        pageIndex--
        paint()
        emitProgress()
        return
      }
      // 本章第一页再往前 = 上一章的最后一页
      const prevChapter = currentChapter - 1
      if (prevChapter < 0) return
      switchChapter(prevChapter)
      pageIndex = Math.max(0, pageCount - 1)
      paint()
      emitProgress()
    },

    next() {
      if (pageIndex < pageCount - 1) {
        pageIndex++
        paint()
        emitProgress()
        return
      }
      // 本章最后一页再往后 = 下一章的第一页
      if (currentChapter + 1 >= chapters.chapters.length) return
      switchChapter(currentChapter + 1, 0)
    },

    goToChapter(index) {
      switchChapter(index, 0)
    },

    goToLocation(location) {
      if (typeof location !== 'number') return
      switchChapter(Math.max(0, chapterIndexOf(chapters.chapters, location)))
    },

    goToPercentage(percentage) {
      // locationsReady 传 true：TXT 的进度由字符偏移直接算出，永远不需要
      // EPUB 那套「索引未就绪就按章节粗跳」的降级
      const target = seekTarget(percentage, {
        locationsReady: true,
        spineLength: chapters.chapters.length,
      })
      if (target.kind !== 'percentage') return
      const offset = offsetFromPercentage(target.percentage, chapters.totalCharacters)
      switchChapter(Math.max(0, chapterIndexOf(chapters.chapters, offset)))
    },

    resize() {
      applyGeometry()
      measurePages()
      paint()
    },

    locationsReady: () => true,

    destroy() {
```

### Task 5: 大文件的分段挂载

> 本任务只在**真的遇到大文件**时才有可观察差异。若手上没有 >10MB 的 TXT，跳过本任务并在进度文件里记下「未验证」，不要假装做过。

**Files:**
- Modify: `src/renderer/src/components/reader/TxtEngine.ts`

**Interfaces:**
- Consumes: Task 3 的引擎
- Produces: 无新接口，改的是 `renderChapter` 的挂载范围

- [ ] **Step 1: 把相邻章节也挂上**

§5.4 说「只挂载当前章节 ±1」。但**多列布局的分页是按整个内容容器算的**，把三章塞进同一个容器会让「本章最后一页」的判断失效。

因此实际做法是：**仍然只挂载当前章**，靠 Task 3 的 `prev`/`next` 在章节边界切换。相邻章节的预挂载对 TXT 没有收益 —— 切换只是一次 `replaceChildren`，几毫秒的事。

**结论：本任务不做预挂载。** 把这条结论写进 §5.4，替换掉「只挂载当前章节 ±1」这句话 —— 那是照搬 EPUB 的思路，对 TXT 不成立。

- [ ] **Step 2: 改成实测结论**

`技术方案文档.md` §5.4 的大文件段落改为：

```markdown
**大文件性能**：策略不是"少加载字符串"，而是**少挂载 DOM**。

渲染进程一次性 `fetch` 转码后的全文（`res.text()`），DOM 里**只放当前章**。
内存里留一个几十 MB 的 JS 字符串不是瓶颈——真正的瓶颈是把全书几十万个 DOM
节点塞进页面。

> 初版这里写的是「挂载当前章节 ±1」。实现时发现对 TXT 不成立：多列布局的
> 分页是按**整个内容容器**算的，三章塞进同一个容器会让「本章最后一页」的
> 判断失效（列数是三章一起算出来的）。TXT 的章节切换只是一次
> `replaceChildren`，几毫秒，没有预挂载的必要。
```

- [ ] **Step 3: 跑验证管线**

Run: `npm run verify`
Expected: 退出 0。

