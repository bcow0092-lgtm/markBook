## 下一步：M4 TXT 阅读

内容：多列分页、大文件分段挂载。**编码检测与章节切分已在 M2 完成**，M4 只剩渲染。

**开工前必读：**

1. 技术方案 **§5.4 第（3）节** —— 多列分页的 CSS 组合**已在 M1 实测确认成立**，确定可用的写法就在那里，直接照抄。**不需要走 `Range.getClientRects()` 二分分页的退路**
2. 技术方案 **§5.7** —— `TxtEngine` 要实现的 `ReaderEngine` 接口（M3 已定稿，不含 `applySettings`）
3. `src/renderer/src/components/reader/EpubEngine.ts` —— 照它的结构写，`goToPercentage` 的降级分支、`destroyed` 检查、`await book.ready` 这类坑都已经踩过

**M4 要点：**

- TXT 的进度是 `字符偏移 / 全书总字数`（`percentageExact` 恒为 `true`），总字数在 `chapters/{id}.json` 里，不用额外扫描
- 大文件的瓶颈在 **DOM 挂载量**不在字符串：一次性 fetch 全文没问题，但只挂载当前章节 ±1
- 阅读页（`src/renderer/src/pages/Reader/ReaderPage.tsx`）目前写死了 `createEpubEngine`，M4 要按 `book.format` 分派

## 未决事项

- M2 只验证了「删除 → 取消」，**没验证过真的删掉之后重启**
- 端到端验证是手工做的，**尚无自动化 E2E**。按 §6.5 的规划，Playwright 的 P0 两条要另起一轮
- **表格兜底没在真机上看过效果**。代码在 `EpubEngine` 的 `rendition.hooks.content` 里给每张表包了 `overflow-x` 容器，但那个 hook 是**每章渲染时触发一次**，要翻到有表格的那一章才看得到。`tests/fixtures/wide-table.epub` 的表格在第二章

## 本机环境注意事项

- **`.npmrc` 里的 `ELECTRON_MIRROR`** —— Electron 二进制从 GitHub Release 直连实测 15 分钟无进展
- **`package.json` 里的 `allowScripts`** —— npm 11 默认拦 postinstall，缺这条 Electron 二进制不会下载
- **Node 24** —— 技术方案 §6.5 原写 20，但 20 已于 2026-04 EOL

## 开发时可用的几样东西

- **渲染进程 console 转发**：开发模式下主进程会把渲染进程的 console 打到终端 stdout（`src/main/index.ts`）。M2 与 M3 修的几个真问题都是靠它发现的
- **样本与生成器**：`tests/fixtures/`，6 个样本 EPUB + `generate.mjs`
- **测试目录分层**：`tests/main/`（node）与 `tests/renderer/`（jsdom，按文件加 `// @vitest-environment jsdom`）。`tests/renderer/makeApi.ts` 是 `MarkReaderApi` 的共用测试替身
- **不要在单元测试里拉 epub.js** —— 一个文件要多花 40 秒
