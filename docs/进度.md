## 下一步：M5 设置与打磨

内容：字号 / 行距 / 页边距、位置保持、空态与异常态。

**开工前必读：**

1. 技术方案 **§5.3** —— 阅读设置的生效方式。「页边距」三档对齐微信读书，EPUB 侧走 `rendition.themes.override('padding-left/right')` + `rendition.resize()`，TXT 侧改 `.txt-columns` 的宽度
2. 技术方案 **§5.7** —— `applySettings` 要**加进 `ReaderEngine` 接口**，M3/M4 刻意没交付空壳方法，现在是补的时候
3. 技术方案 **§5.2 的坑 2** —— **改设置会丢位置**，必须走「存位置 → 应用 → 恢复」。这是 `applySettings` 收进接口的唯一理由，两侧都要实现

**M5 要点：**

- `ReaderSettings` 已经在 `shared/types.ts` 里（`fontSize` / `lineHeight` / `pageMargin`），IPC 通道 `settings:get` / `settings:save` 也已接好（M1 就铺好了），M5 只需要做 UI 与生效逻辑
- TXT 的「页边距」就是改 `.txt-columns` 的 width（§5.3 说单栏居中下改列宽与改页边距等价）
- 空态与异常态：书架空态 M2 已做；阅读页的「文件损坏 / 打不开」还没有处理

## 未决事项

- M2 只验证了「删除 → 取消」，**没验证过真的删掉之后重启**
- **表格兜底始终没在真机上看过效果**。代码在 `EpubEngine` 的 `rendition.hooks.content` 里给每张表包了 `overflow-x` 容器，但那个 hook 是**每章渲染时触发一次**，要翻到有表格的那一章才看得到。`tests/fixtures/wide-table.epub` 的表格在第二章
- **TXT 的页码换算是近似值**：精确到页不精确到字符，误差上限约 0.05% 全书。要精确得用 `Range` 量列边界，代价是每次翻页都算一遍，不值得 —— 这一点在 `txtPaging.ts` 的注释里写明了
- 端到端验证是手工做的，**尚无自动化 E2E**。按 §6.5 的规划，Playwright 的 P0 两条要另起一轮

## 本机环境注意事项

- **`.npmrc` 里的 `ELECTRON_MIRROR`** —— Electron 二进制从 GitHub Release 直连实测 15 分钟无进展
- **`package.json` 里的 `allowScripts`** —— npm 11 默认拦 postinstall，缺这条 Electron 二进制不会下载
- **Node 24** —— 技术方案 §6.5 原写 20，但 20 已于 2026-04 EOL
- **`gh` 已装但要注意 PATH**：`/c/Program Files/GitHub CLI/gh.exe`。会话若在安装前启动，PATH 里没有它，得用全路径

## 开发时可用的几样东西

- **渲染进程 console 转发**：开发模式下主进程会把渲染进程的 console 打到终端 stdout（`src/main/index.ts`）。M2–M4 修的每个真问题都是靠它发现的
- **样本**：`tests/fixtures/` 有 6 个样本 EPUB 与生成器；TXT 样本用 `iconv-lite` 现场造即可
- **测试目录分层**：`tests/main/`（node）与 `tests/renderer/`（jsdom，按文件加 `// @vitest-environment jsdom`）。`tests/renderer/makeApi.ts` 是 `MarkReaderApi` 的共用测试替身
- **不要在单元测试里拉 epub.js** —— 一个文件要多花 40 秒
